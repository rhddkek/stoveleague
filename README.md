# 스토브리그

한국·일본·대만·미국 리그 가운데 구단 하나를 골라 단장으로 유망주를 발굴·육성·판매하고 우승까지 키워 가는 싱글플레이 구단 경영 게임입니다. 정규 시즌은 리그마다 실제 경기 수(한국 144 · 일본 143 · 대만 120 · 미국 162)와 실제 가을야구 방식(한국 5팀 계단식, 일본 클라이맥스 시리즈 → 일본시리즈, 미국 리그별 6팀 → 월드시리즈, 대만 전·후반기 → 대만시리즈)을 따릅니다(v48~). 한국은 1군 10개 구단 단일 리그 + 2군(승강제 없음).
결과물은 HTML 파일 하나(`stoveleague.html`, 같은 내용 `index.html`)이며 서버 없이 브라우저에서 바로 실행됩니다.

- **플레이**: https://rhddkek.github.io/stoveleague/ (테스트 모드 `?test=1`)
- **GPT·Claude 공동 작업**: [`review/README.md`](review/README.md) · 상태판 [`review/STATUS.md`](review/STATUS.md)

## 선수단·리그 환경 (v95~v96)

- **선수단 고정**: 새 게임의 모든 구단 선수는 구단 이름에서 나온 고정 난수(`BAL.ROSTER_SEED`)로 만든다 → 시드·맡은 구단과 상관없이 같은 선수. 시드는 시즌 운·FA·신인만 바꾼다. 고급 설정 「선수단 무작위」(`opt.randRoster`)는 예전 방식
- **실존 선수와 1:1 대응 금지**: 실제 데이터는 리그 단위(득점·타율·리그 1위 기록 수준)로만 쓴다 — `BAL.ENV`(리그별 안타·홈런·존·컨택·거포 가산)와 `BAL.STARS`(리그 간판 스타 수). 근거·측정값은 `review/수정기록/v95.md`·`v96.md`
- 선수 생성·구단 구성을 바꾸면 리그 환경을 다시 재야 한다 (같은 시드 시즌 자동 진행으로 리그별 득점·타율 측정)

## 빌드·검증

```bash
npm install          # jsdom (화면 테스트용)
npm run build        # stoveleague.html 생성
npm test             # 빌드 후 전체 검증
```

## 고정 규칙

- 실존 선수·구단명·로고를 쓰지 않는다. 해외 리그 이름·규모는 실제를 따르되 구단은 「실제 연고 도시 + 가상 애칭」.
- 선수는 국가·리그를 옮겨도 같은 ID로 기록·관계(옛 제자·셀온)가 유지된다.
- 이적은 돈·소속·계약을 한 번에 처리한다.
- 시즌 성장·동계훈련·겨울리그 파견 성장은 겹치지 않는다(파견 시 동계훈련 대체).
- 저장 형식을 바꾸면 `VERSION`을 올리고 `migrate()`에 변환을 넣으며, 구버전 세이브 샘플로 검증한다. 변환 실패 시 원래 상태를 보존한다. (예외: v28 10구단 개편은 광우 결정으로 v27 이전 저장을 안내 후 거부)
- 수정 후에는 `npm test`가 전부 통과해야 배포한다.
