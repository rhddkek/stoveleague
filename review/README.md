# GPT · Claude 공동 작업 방식

스토브리그는 **GPT가 플레이하고 요청을 쓰고, Claude가 고치고 기록하는** 방식으로 다듬습니다.
광우는 둘 사이에서 한마디만 전하면 됩니다. 복사·붙여넣기를 줄이는 게 목적입니다.

## 역할

| 누가 | 하는 일 | 쓰는 곳 |
|---|---|---|
| GPT (테스터·기획 리뷰) | 실제로 플레이하고 문제·제안을 요청서로 씀. 고친 뒤 다시 확인(재검토) | `review/요청/` |
| Claude (개발) | 요청을 읽고 고침 → 테스트 전부 통과 → 배포 → 무엇을 어떻게 고쳤는지 기록 | `src/`, `test/`, `review/수정기록/`, `review/STATUS.md` |
| 광우 (결정) | 방향 결정, 둘에게 신호 전달 | — |

## 한 바퀴 흐름

1. **GPT 테스트** — 플레이 주소에서 플레이하고 `review/요청/`에 요청서를 남긴다. (양식: `review/요청/_양식.md`)
   - GPT가 저장소에 직접 쓸 수 없으면, 요청서 내용을 채팅에 마크다운으로 출력 → 광우가 Claude에게 그대로 붙여 넣는다. Claude가 파일로 저장한다.
2. **광우 → Claude: 「요청 반영해」**
   - Claude는 `STATUS.md`에서 상태가 「접수」인 요청을 모두 처리하고, 버전을 올려 배포한 뒤 `review/수정기록/vNN.md`를 쓰고 `STATUS.md`를 갱신한다.
3. **광우 → GPT: 「재검토해」**
   - GPT는 최신 `수정기록`을 읽고 새 버전에서 항목마다 확인한 뒤, 요청서 아래 「재검토」 칸에 **통과 / 재요청(이유)** 을 적는다.
4. **광우 → Claude: 「재검토 반영해」**
   - 「통과」는 완료 처리, 「재요청」은 다시 고친다.

## 상태 이름

`접수` → `진행` → `수정됨(vNN)` → `완료` (재검토 통과)
그 밖에: `재요청`(재검토에서 다시 열림) · `보류`(광우 결정 필요 또는 나중) · `반려`(규칙 위반·중복, 이유 적음)

## 공통 규칙

- 실존 선수·구단명·로고는 쓰지 않는다. 해외 리그는 실제 이름·규모, 구단은 「실제 연고 도시 + 가상 애칭」.
- 세이브 호환은 반드시 지킨다. 업데이트로 기존 저장이 깨지면 안 된다.
- 요청은 **화면에서 본 그대로**(문구·숫자)와 **재현 방법**을 적는다. 추정은 추정이라고 쓴다.
- 기능 추가보다 "플레이어가 매주 내 선택 때문에 선수가 달라졌다고 느끼는가"를 우선한다.
- 광우에게는 존댓말.
